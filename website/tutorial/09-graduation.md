# 业务接入与验收

Agent 在本机能够运行后，还要检查业务接口、权限、异常路径和部署环境。这里整理把示例改造成实际业务系统时需要完成的工作。

## 1. 接入自己的业务

1. 将查询、写入等业务能力实现为 `app/` 中的 Tool，明确输入校验、权限、超时和幂等策略。
2. 调整 Agent 定义中的人设、工具、模型槽位与知识配置，导入后确认工作台中的版本。
3. 固定步骤和金额计算放在业务代码或 LangGraph 流程中；涉及多个职责时再设计团队委派。
4. 通过 REST / SSE 对接现有客户端；高风险操作同时对接人工审批，不要只消费最终回复而忽略审批事件。

具体方式见[接入业务系统](../manual/customization/business-integration.md)、[编写工具](./04-write-a-tool.md)和[流程与团队](./07-graphs-and-teams.md)。

## 2. 上线验收清单

| 检查项 | 应保留的验证证据 |
| --- | --- |
| 正常调用能完成，定义与版本可追溯 | API / SSE 响应与对应 Run / Trace |
| 工具输入不合法、未授权时不执行 | 负向测试输出、业务接口记录 |
| 高风险工具未经审批不能执行，拒绝和超时有明确结果 | 审批事件、执行记录与异常用例 |
| 确定性流程顺序正确；使用团队时委派符合预期 | 流程与团队的成功、失败、取消用例 |
| 知识检索命中、无命中和灰色问题符合业务预期 | 使用实际语料校准的检索结果与评测报告 |
| 修改人设、模型或工具后没有破坏关键行为 | 同一评测集的前后对比 |
| 预算、超时、取消与恢复满足业务要求 | 限额和异常路径的运行记录 |
| 凭据、网络访问、日志与备份配置正确 | 脱敏配置、健康检查、备份恢复演练 |
| 升级后业务代码与数据仍然可用 | 合并记录、迁移结果、回归报告与回滚方案 |

按项目实际使用的能力选择检查项。不要把示例中的阈值、固定回复或评测通过率直接当成生产质量标准。
