# 第 5 课：给 Agent 加知识——RAG 与防错答守门

> 学完本课你能：把一份规章文档变成可检索的知识库挂到 Agent 上；用检索测试接口亲手校准阈值；配置三道守门让 Agent「宁可说不知道，不硬编答案」 ｜ 预计耗时 45 分钟 ｜ 前置：第 4 课 ｜ 难度 ★★☆

## 引子：一个自信的编造者

拿真模型问问小图："书能借多久？"它会回答——但答案来自模型的训练记忆，跟你们学校图书馆的真实规章**没有任何关系**。你所在学校规定借期 45 天，它可能告诉你 30 天，还带着笃定的语气。再问"逾期怎么罚"，它编一个听起来合理的数字。罚金标准这种事，编错了是要跟真人对峙的。

这类问题的共性值得看清楚：它们**不是常识题，是你的组织的内部事实**。模型读过的互联网里没有你们学校的借阅规章，也不会有你们公司的报销制度、你们产品的费率表——而用户默认它知道。 Agent 越好用，这种“自信的不知道”就越危险。

这就是第 0 课说的幻觉，而且是小图现在最致命的短板：人设让它开口，工具让它做事，可它脑袋里装的世界知识是模型的，**不是你的**。凡是"你的组织才有的事实"——规章、政策、费率、流程——模型一概不知道，又从来不承认不知道。

解决思路第 0 课推演过：把规章文档切块入库，用户提问时检索最相关的几块塞给模型，让它**看着材料答题**——看不见材料的问题，宁可拒答。这一课你会走完 RAG 的全链路：上传 → 切块 → 检索实验 → **校准阈值** → 守门配置 → 亲眼看着它拒答。

一个类比先放在这：给 Agent 配知识库，很像给新员工发一本业务手册。发手册不难，难的是两件事——手册怎么编（切块：一页杂糅十个主题的手册谁也查不动）、新员工什么话该说（守门：手册上没有的，是承认“我查一下”还是现编一个）。这一课的全部内容就是这两件事。

其中"校准阈值"是这一课真正的主角，也是很多人用 RAG 最容易偷懒跳过的一步——网上抄一个 0.7 就上了。跳过的后果是守门形同虚设：该挡的没挡住，不该挡的误杀了。我们不会跳，而且你会用真实实验数据明白**为什么不能跳**。

还有一个心理准备：这一课你会看到不少分数（0.101、0.128、0.195……）。别被数字唬住，也别去背——这些值只对这套语料、这种切分负责。这一课真正要你带走的是**得到这些数字的方法**：换你的语料，数字全变，方法不变。

## 开始前，先想三个问题

凭直觉猜，本课第 2 节和步骤里会揭晓：

1. 同一份规章文档，切块从 2 块改成 6 块，"反例分数比正例还高"的怪象为什么会消失？
2. 步骤 7 那句拒答"我在馆藏规章里查不到依据"——是模型说的，还是代码说的？这次对话花了多少 token？
3. 在人设里写一句"不知道就说不知道"，为什么第 0 课就验证了拦不死？这一课的三道守门和这句 Prompt 差在哪？

第 1 题在第 2 节揭晓，第 2 题在步骤 7 揭晓，第 3 题在「框架为什么这样设计」揭晓。

三个问题对应本课的三块能力：切块决定检索质量、守门决定下限、代码执行决定这条底线守不守得住。

## 1. 学习目标

- 把一份 Markdown 规章变成知识库并挂到 Agent
- 用检索测试接口做对比实验：换切块参数，看分数怎么变
- 理解三道守门（阈值 / 兜底拒答 / 引用编号）各挡什么，以及它们为什么必须是代码而不是 Prompt
- 亲眼验证 `knowledge.no_hit` 事件与零 token 拒答

## 2. 概念讲解：阈值是调出来的，不是拍出来的

RAG 的链路你已经在第 0 课推演过（切块 → 向量化 → 检索 → 注入）。这里讲链路上最容易做错的一环：**相似度阈值**。

检索返回的每个片段带一个相似度分数（cosine，0 到 1）。分数多高算"相关"？这没有万能答案——它取决于你的 embedding 模型、你的语料、你的切块参数。**唯一可靠的办法是实测**：拿几个"应该命中"的问题和几个"不该命中"的问题各查一遍，看分数分布，把阈值卡在两团分数中间。

这听起来繁琐，但下面的真实实验会告诉你，跳过它的代价是什么。更重要的是切块对分数的影响。我们马上会做一个真实实验：同一份规章，切成 2 大块时，"书能借多久"（正例）得分 0.101，"怎么开发票"（反例）得分 0.128——**反例反而更高**，此时无论阈值定多少守门都是坏的。切成 6 小块后，正例升到 0.195-0.309，反例掉到 0.126 以下——分界清晰了。直觉上不难理解：块越大，一块里混杂的主题越多，向量就越"什么都有点像、什么都不像"。

开头的第 1 题答案就在这组数字里：不是阈值变聪明了，是**向量本身变干净了**。2 块切分时，"借阅期限"和"校园卡补办"挤在同一块里，这块的向量既像借期问题又像开票问题——比"开票"还像借期，因为混杂的成分太多。切成 6 块后，每块只讲一个主题，向量的"个性"立起来了，正例反例各自归团。**先有干净的块，才有能用的阈值**——顺序反了，怎么调都是白调。

三道守门各挡什么：

- **`score_threshold`**（阈值）：低于阈值的片段直接丢弃，不进模型的上下文。
- **`no_hit_fallback`**（兜底拒答）：过滤后一个片段都不剩时，**代码直接用这句话作答，模型根本不出场**——零 token、零发挥空间。事件流里能看到 `knowledge.no_hit`，Run 的结束原因是 `knowledge_no_hit`。
- **`cite: true`**（引用编号）：命中时模型被要求只依据编号片段作答、答案带 `[n]` 引用——用户能核对出处。

注意这三道防线的实现位置：全在模型出场**之前或之外**，由代码执行。对比"在 Prompt 里写'你不知道就说不知道'"——第 0 课验证过那拦不死。这就是"确定性规则由代码执行"在 RAG 上的落点。

把三道防线在链路上的位置画出来，纵深关系一目了然：

```text
用户提问
   ↓ 检索（检回 top_k 片段，各带分数）
【第一道】score_threshold：低分片段丢弃 ← 减少干扰
   ↓ 过滤后的片段
【第二道】no_hit_fallback：一个不剩？直接用兜底话术拒答，模型不出场 ← 零 token
   ↓ 至少剩一块，作为编号材料注入上下文
【第三道】cite: true：模型只能依据编号片段作答，答案带 [n] ← 可核对
   ↓
模型组织答案
```

三道防线各管一段：前两道完全不依赖模型，第三道是对出场模型的强约束。这就是「宁可说不知道，不硬编答案」能硬起来的原因——它不是对模型的期望，是对流程的控制。

### 框架为什么这样设计

三个设计点，每一个都堵着一类常见的 RAG 事故：

**阈值为什么要校准而不是拍一个"推荐值"？** 因为相似度分数**没有跨场景的量纲**。同一个 0.15，在 FakeEmbedding 的这套语料上是清晰分界，换一个 embedding 模型可能意味着完全不同的相关度——不同模型打出的分数分布天差地别。任何"通用推荐阈值"都隐含了一个不成立的假设：分数含义不随模型、语料、切块变。所以框架不给你推荐值，给你的是校准工具（检索测试接口）和校准方法（正例反例两团分数），把可靠的那部分——你的实测——变成配置。步骤 4 那句"你自己的校准记录比任何推荐值都可靠"，说的就是这个。

**守门为什么放在代码里，而不是写进 Prompt 让模型自己把关？** 开头的第 3 题答案在这：Prompt 约束是概率性的，模型面对一个"似是而非"的问题时，恰恰是最想硬编的时候，也正是 Prompt 约束最失灵的时候——你等于把保险栓装在最不可靠的环节上。代码守门不同：片段过不了阈值就是进不了上下文，片段全被滤光模型就不出场，模型连"硬编一次"的机会都没有。**护栏的位置要选在事故发生之前，而不是之后。**

**为什么切块参数（大小/重叠）按知识源独立配置，而不是全局一套？** 因为不同文档的「天然粒度」不同：规章 FAQ 一条一段，切成 120 正合适；合同条款动辄几千字一段，同样参数可能把一条完整条款拦腰切断。全局参数意味着所有文档迁就一个值，结果是谁都不合适。按源配置让每种文档用自己的最优切分——步骤 4 调参时你只需要动这一份文档，不用怕殃及其他知识源。

**为什么 `no_hit` 时宁可直接短路、让模型完全不出场？** 两个账。安全账：检索全空说明语料里没有依据，此时让模型出场，它只能靠训练记忆或脑补——正是要消灭的行为。成本账：拒答不该花钱，一次对话几厘钱听着不多，高频客服场景乘上每天几万次就是真账单。短路之后，兜底话术零 token、零发挥空间，事件流里留下 `knowledge.no_hit` 完整现场，事后可审计。安全与成本在同一处收口。

### 关于本课的 FakeEmbedding：演示向量与真实向量的边界

本课所有分数都是在 FakeEmbedding（框架内置的确定性演示向量）下实测的。它的定位要说清楚：**够你把链路、守门、校准方法完整跑通，不承诺生产检索质量**。

切换到真实 embedding 模型用环境变量 `EMBEDDING_MODEL` 配置（可选配 `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY_ENV`）。但注意：换了向量模型，库里的旧向量、检索分数、你校准的阈值——全部作废，必须重新灌库、重新跑步骤 3 的实验、重新定阈值。这一课教你的校准闭环，就是为那一天准备的。

## 3. 动手：主线步骤

### 步骤 1：准备规章文档

新建 `library-rules.md`（放哪都行，上传后就用不着本地文件了），内容是一份小型借阅规章：

```markdown
# 图书馆借阅规章

## 借阅期限与数量
- 本科生可同时借阅 10 册，借期 30 天
- 研究生可同时借阅 20 册，借期 45 天
- 教职工可同时借阅 30 册，借期 60 天

## 续借规则
- 每册图书可续借 1 次，续借期与原借期相同
- 有他人预约的图书不可续借
- 逾期图书不可续借

## 逾期处理
- 逾期图书按每天每册 0.1 元收取滞纳金
- 逾期超过 30 天的，冻结借阅权限直至归还并缴清滞纳金

## 预约与委托借阅
- 已借出的图书可在线预约，归还后为你保留 3 天
- 本馆未收藏的图书可通过馆际互借申请，处理周期约 5 个工作日

## 校园卡
- 校园卡丢失请立即挂失，挂失期间产生的借阅记录由持卡人负责
- 补办新卡收取工本费 20 元，三个工作日后凭学生证到前台领取

## 馆内服务
- 自习区开放时间：周一至周日 7:00-22:30
- 电子阅览室需刷校园卡进入，每人每日限用 4 小时
```

这份文档的结构是有意的：一节一个主题，标题就是主题名。记住这个样子——步骤 4 你会看到，RAG 检索质量的第一决定因素不是参数，是文档本身长得像不像"一节一题"。

### 步骤 2：上传到知识库

工作台**知识库页 → 上传**：选这个文件，名称填 `library-rules`，切块大小 300 / 重叠 30（先按这个来，马上会调），描述随意。

不想点页面的话，等价的 API：

```bash
curl -X POST http://localhost:8000/v1/knowledge/sources \
  -F "files=@library-rules.md" -F "name=library-rules" \
  -F "description=图书馆借阅规章" -F "chunk_size=300" -F "overlap=30"
```

✅ 你应该看到：返回 `"chunk_count": 2`——这份 993 字节的文档被切成了 2 块。记住这个数字，它马上会成为问题。

2 块意味着什么？回头看步骤 1 的文档：六个章节被强行压进两大块，「借阅期限」旁边住着「校园卡补办」。这就是开头第 1 题埋的伏笔——问题不在阈值，在块里。

### 步骤 3：检索实验——发现问题

知识库页的**检索测试**面板（或 API `POST /v1/knowledge/query`）逐个查这几个问题，记下每个的 top1 分数：

```bash
for q in "书能借多久" "怎么续借" "食堂几点吃饭" "怎么开发票"; do
  echo "Q: $q"
  curl -s -X POST http://localhost:8000/v1/knowledge/query \
    -H "Content-Type: application/json" \
    -d "{\"source\": \"library-rules\", \"query\": \"$q\", \"top_k\": 3}" \
    | python3 -c "import sys,json; r=json.load(sys.stdin); print('  ', round(r[0]['score'],3), r[0]['content'][:30])"
done
```

前两个是正例（语料里有答案），后两个是反例（语料里根本没有）——**校准的本质就是拿这两类问题量出两团分数**。

命令里那段 `python3 -c ...` 不用细看：它只是把返回 JSON 里 top1 的分数抽出来、保留三位小数打印，方便你横向对比。重点看的是每个问题的分数和分数背后的格局。

✅ 你应该看到（FakeEmbedding 下的实测值，你的数字会略有出入但格局相同）：正例"书能借多久"约 0.10，反例"怎么开发票"约 0.13——**反例分数更高，两团分数糊在一起**。此刻阈值无论定多少，要么放走反例、要么误杀正例。2 块的切分把不相关的内容挤进了同一块，向量失去了区分度。

这就是"拍阈值"的下场预演：如果你没做这步实验、直接抄了个 0.5 上线，你不会知道守门从第一天起就是坏的——反例照样高分过线，模型照样拿着不相关的片段硬编。

顺带看一眼第四个问题「食堂几点吃饭」的分数——记住它的量级，步骤 4 之后它会变得更有说服力。

### 步骤 4：调切块，重做实验

把切块改小——知识库页的"重新切块"（改参数不重新上传，文件已在服务端）：

```bash
curl -X POST http://localhost:8000/v1/knowledge/sources/library-rules/rechunk \
  -H "Content-Type: application/json" -d '{"chunk_size": 120, "overlap": 12}'
```

重跑步骤 3 的实验。

✅ 你应该看到：`chunk_count` 变成 6；正例升到 0.20-0.31 区间，反例掉到 0.13 以下（"食堂几点吃饭"直接 0.0）。**两团分数分开了，阈值有地方卡了**。把你实测的两组数字记下来——这是你自己的校准记录，比任何教程给的"推荐值"都可靠。

校准记录怎么记？一张三列表就够：问题、top1 分数、正/反例。比如：

| 问题 | top1 分数 | 类别 |
|---|---|---|
| 书能借多久 | （填你实测的） | 正例 |
| 怎么开发票 | （填你实测的） | 反例 |

将来任何人问起「你这个阈值哪来的」，把这张表甩出来——它就是答案。

阈值不是抄来的，是量出来的——这节课反复说的就是这一句话。

注意操作顺序的含义：先实验、发现问题（2 块切分），再调参数、验证修复（6 块切分）。以后你换 embedding 模型、换文档，重复的就是这个闭环——**实验发现问题，参数修复问题，实验确认修复**，不是反过来"先调参数再看运气"。

### 步骤 5：配置守门并挂载

`app/agents/my_lib_assistant.yaml`：人设里加一句使用规则，加 `knowledge` 段（阈值用你自己的校准结果，下面是本教程语料的实测值 0.15）：

```yaml
instruction: |
  ...（前几行不动）
  规章问题依据知识库检索到的片段作答，引用带 [n] 编号；检索不到就说不知道，不编。
  ...
knowledge:
  sources: [library-rules]
  top_k: 3
  # 0.15 是 FakeEmbedding 对本语料 6 块切分的实测分界（正例 0.195-0.309 / 反例 <=0.126）
  # 换 embedding 模型或扩文档后必须用 /v1/knowledge/query 重新校准
  score_threshold: 0.15
  no_hit_fallback: 抱歉，这个问题我在馆藏规章里查不到依据，建议到图书馆前台咨询确认。
  cite: true  # 默认开，引用标注（答案带 [n] 编号）；显式写出便于对照三个守门字段
```

配置里的那两行注释不是给人看的客套——将来某个同事看到 0.15 这个数字，第一反应一定是"这数哪来的"，注释回答的是**这个值的适用边界**：哪套语料、哪种切分、哪个 embedding 模型。条件一变就得重测，注释把这句话钉在配置原地。

导入：

```bash
.venv/bin/luban init
```

✅ 你应该看到：`my-lib-assistant` 版本 +1，工作台编辑器的“记忆与知识”区能看到三个守门字段。

到这一步值得停下来核对一遍你手里的东西：一个 6 块的知识库、一组你亲手量出来的分数、一个卡在两团分数中间的阈值、三道各司其职的守门。RAG 的“配置工作”到此全部结束——接下来的步骤都是验收。

### 步骤 6：命中——看着材料答题

调试台问小图：`书最多能借多久？我是本科生`

✅ 你应该看到：回复类似"本科生可同时借阅 10 册，借期 30 天**[1]**"——数字来自你的规章文档，`[1]` 是引用编号。这个回答模型"编"不出来：它只见过检索给它的那一小块文本。

`[1]` 这个小编号是个被低估的设计：它同时干了两件事——给用户**核对出处**的入口（点过去能看原文），给模型**只能依据材料**的约束（要求带编号，就是要求只从编号材料里说话）。第 6 课的评测里，引用是否出现还能变成机器可判的断言。

再看一眼回答里的数字本身：10 册、30 天——去对照步骤 1 的文档原文，一字不差。命中场景下你的验收标准就一条：**答案里的每个事实性断言都能在检索片段里找到原文**。找不到的，无论多像真的，都按幻觉处理。

### 步骤 7：未命中——代码守门，模型不出场

问一个语料里完全没有的问题：`食堂几点开门吃饭`

✅ 你应该看到：回复**一字不差**是你配的 `no_hit_fallback` 那句话。看事件流（curl 或调试台）：`knowledge.no_hit` 事件带完整现场——`{"sources": ["library-rules"], "score_threshold": 0.15, "hits_raw": 3, "hits_kept": 0}`（检回 3 块、阈值后 0 块）；**没有 token.delta**——模型根本没被调用，这次拒答零成本、零发挥空间。Run 结束原因 `knowledge_no_hit`。

开头的第 2 题在这里揭晓：拒答是**代码说的**，模型全程没出场——`hits_kept: 0` 之后框架直接取兜底话术收尾，事件流里没有任何 token.delta 就是铁证。你在步骤 5 写的兜底话术，此时是这段对话里唯一的"答案来源"。

### 步骤 8：故意把守门弄坏，再看一遍

把 YAML 里阈值改成 0.05，init，重问"食堂几点开门吃饭"。

✅ 你应该看到：这次没有拒答——低分片段被放行，模型拿着不相关的规章片段开始"凑答案"（可能聊到自习区开放时间之类的）。看完把阈值改回 0.15。这一趟不是白走：你现在对"阈值松一格会发生什么"有体感了，以后看到 Agent 开始似是而非地答非所问，第一反应应该是查阈值。

这一步故意制造的就是生产里最常见的 RAG 事故：没人动过文档、没人动过人设，就因为阈值不设防，Agent 从"守规矩的咨询员"退化成"什么都要接一句的 amateur"。**0.15 到 0.05 之间，隔着一个事故。**

顺便把破坏实验的结论格式化：三道守门里，阈值是唯一需要你给出数字的一道——也因此是唯一可能被你写错的一道；兜底话术和引用编号是配置即生效，没有校准问题。三道里唯一会静默失效的就是阈值，这就是它值得整节课篇幅的原因。

## 4. 完成自检清单

- [ ] 知识库里 library-rules 显示 6 块（chunk_size 120）
- [ ] 检索实验记录在案：正例/反例两组分数，阈值卡在中间
- [ ] 命中问题带 [n] 引用，数字与文档一致
- [ ] 未命中问题走 no_hit：兜底话术原样返回、事件流有 knowledge.no_hit、无 token.delta
- [ ] 故意调低阈值的破坏实验做过并恢复了

清单用法和前两课一样：逐条动手验，尤其最后一条——破坏实验做了又恢复，才算真懂了阈值在守什么。带着“没坏过所以不懂坏了什么样”的状态上生产，是 RAG 事故最常见的起点。

## 5. 常见坑

这一课的坑有一个共性：**把「配置对了」当成「守门有效」**。配置正确只是必要条件，守门是否真有效，只有你的校准数据能证明。逐个看：

**阈值照抄教程/别人的值。** 本课的 0.15 只对本教程的语料和切块负责。你的文档、你的切块、将来换真 embedding 模型——任何一个变了都要重跑步骤 3 的校准。照抄阈值是守门失效的第一大原因。

**正例反例分不开。** 回到切块：块太大就调小；还不行检查文档本身是不是"一锅烩"（一章塞了十个主题）——RAG 喜欢结构清晰、一节一题的文档。

**"应该拒答"的问题被答了。** 先查检索测试接口看这个问题的实际分数，分两种情况。像本课的"怎么开发票"：6 块切分下实测 0.126，top3 全低于 0.15 阈值——它被"阈值 + 兜底话术"这道**代码防线直接短路**了（`knowledge.no_hit`，模型根本没出场，你看到的是兜底话术原文），这道功劳簿上没有人设。另一种是真正过了阈值的灰色地带（措辞和某条规章擦边，相似度就是高，比如"滞纳金""工本费"这类词会把不相关问题抬过线）——这时才轮得到人设出场，它是纵深防御的第二道，接的是阈值漏下来的问题，不是替守门收尾的。灰色地带的处理是业务决策：把话术写细让人设兜住，或接受它答。

**改了 YAML 里的 knowledge 段没生效。** 老朋友了：`luban init`。

**换文档后分数全变了。** 正常，重新校准。知识库页改参数重新切块很快，别攒着不调。校准记录（步骤 4 那张表）同步更新，别让配置和记录打架。

## 6. 动手练习

三个练习沿主线往外扩：A 验证「知识是数据」，B 摸索 top_k 的手感，C 为第 6 课备料——C 的三个对抗问题下一课直接进评测集，现在多花的时间后面会加倍还给你。

**练习 A（模仿）**：给规章加一条新规定（比如"寒暑假借期自动延长 15 天"），重新切块，问对应问题验证回答更新了。体会：**知识更新不用改代码、不用改人设、不用重新部署**——这就是"知识是数据"的含义。

**练习 B（变式）**：把 `top_k` 从 3 调成 1，再问一个跨两条规定的问题（"我逾期了还能续借吗"——答案需要"逾期不可续借"+"滞纳金"两块）。观察回答质量的变化，理解 top_k 是"给模型几块材料"的预算。

**练习 C（综合，为第 6 课铺垫）**：设计 3 个你自己的对抗性问题——措辞上像规章问题、内容上语料没有（比如"图书馆能代收快递吗"）。用检索测试接口查它们的分数，看你的阈值守不守得住。把这三个问题记下来——第 6 课它们会变成你评测集里的 `expect_refusal` 用例，从"手动抽查"升级成"每次改动自动回归"。

## 7. 思考题

概念题，先自己想，再看括号里的提示：

1. **`cite: true` 的引用编号，对用户的价值和对模型的价值分别是什么？去掉它，哪一类质量问题会变得难以发现？**（提示：对用户是"可核对"，对模型是"只能依据编号材料说话"；去掉后"模型夹带训练记忆作答"这件事你从答案表面上看不出来了。）
2. **换用真实 embedding 模型后，旧阈值 0.15 还能用吗？除了重调阈值，手册为什么还强调"重新灌库"？**（提示：不同模型打出的分数分布完全不同，0.15 在新模型下可能意味着"完全不相关"；向量也是旧模型生成的，库里的向量和查询向量得是同一套语义空间。）
3. **`max_age_days`（知识时效）和 `no_hit_fallback` 组合使用，挡住了哪两类典型事故？**（提示：前者挡"规章改了但旧片段还在库里被检索到"——过期知识照答；后者挡"库里压根没有依据还硬编"——无中生有。一个是答旧的，一个是编新的。）

## 8. 小结与下一课预告

开头三个问题，现在回收：

- **第 1 题**：切块从 2 到 6，变的不是阈值是向量——每块只讲一个主题，向量的区分度才立起来，正例反例各自归团。**先有干净的块，才有能用的阈值。**
- **第 2 题**：拒答是代码说的。`hits_kept: 0` 后框架直接取 `no_hit_fallback` 收尾，模型没出场，事件流里没有 token.delta——零成本、零发挥空间。
- **第 3 题**：Prompt 约束是概率性的，恰好在模型最想硬编的时候最失灵；三道守门全在模型出场**之前或之外**由代码执行——片段进不来、模型不出场、答案带编号，模型连硬编的机会都没有。

小图集齐了三块能力：人设（谁）、工具（手）、知识（脑外挂）。更重要的是你掌握了防错答的完整工事——阈值挡低分、兜底拒答挡全空、引用编号逼模型亮出处，三道全是代码守的。

把这一课的动作收成一张速查卡，以后每次换语料/换模型/扩文档，跑的就是这个闭环：

1. 上传文档，选一个初始切块参数；
2. 挑正例反例各几个，用检索测试接口量两团分数；
3. 分不开？调切块，重测；分开了？把阈值卡在中间；
4. 配三个守门字段，init；
5. 各验一次命中与未命中，看事件流。

但你现在守护质量的方式还是**手动抽查**：改了人设，自己问几句看看。改的东西多了、要看的行为多了，手动就守不住了。下一课把抽查固化成**评测集**：每个问题配上机器可判的断言，一条命令全量回归，还能对比两个版本谁好谁坏。你第 5 课练习 C 的三个对抗问题，到时候直接派上用场。
