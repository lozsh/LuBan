# 开发者工作台

> 本页讲 Web 控制台的管理页面与用户端聊天入口、登录鉴权、Agent 调试台、日志排查、用户权限、虚拟形象，以及调试相关的几个会话约定。

> 新手路径：第一次把工作台跑起来见 [本地运行](../../tutorial/01-setup-and-first-run.md)。

Web 控制台：Agent 定义编辑与调试（调试台为「对话 + Prompt 试跑」双 Tab 工作台）、模型对比试跑、Prompt 库管理、Tool/MCP 在线测试、Skill 管理（上传/版本/分配）、知识库管理（上传/切块/重切/检索测试，见[知识与记忆](./knowledge-memory.md)）、流程图（确定性流程的只读拓扑视图）、Trace 可视化、评测报告查看、日志排查、用户权限管理。前端页面路由当前实测为 17 条，其中 `/diagnostics` 和 `/security` 是平台排查与访问控制入口，`/chat` 是并列的用户端聊天入口。

**鉴权闭环**：后端开启 `AUTH_ENABLED=true` 后支持两种登录方式：`admin` 等数据库账号登录，或继续使用 API Key。账号令牌和 API Key 都只保存在当前页面内存，不写 localStorage、不进 URL、不进构建产物；账号令牌优先，刷新页面需重新登录或重新提供 Key。登录/登出/切换身份时，页面会清空上一账号留在内存里的私密数据与查询缓存，再以新身份重新拉取，不会复用旧账号的缓存。REST、SSE 流、上传/头像等请求共用同一身份来源（`Authorization: Bearer <token-or-key>`）；收到 401 不会自动重试。`AUTH_ENABLED=false` 是开发模式：后端放行匿名主体，UI 会说明开发模式；生产必须保持 `true`。

**平台 RBAC**：`/security` 页面管理用户、角色和权限。内置 admin 拥有全部 10 个权限；operator 覆盖配置、运行、审批、诊断和评测；auditor 只读并可看诊断；viewer 只读且不能看诊断。菜单和 `/diagnostics`、`/security` 路由 guard 只是无权限时不显示、不进入；后端仍会在每个 `/v1` 请求上重载用户状态、角色授权并返回 403。权限是平台级开关，不做部门、租户或行级数据隔离。

**日志排查页面（/diagnostics）**：分 Run 和日志两个 Tab，两个列表各自独立分页（每页 20 条，翻页是真实的新请求，`total` 来自后端响应）。Run Tab 按会话、Run、Trace、用户标签、状态过滤；日志 Tab 额外支持请求 ID、时间范围和关键词过滤。详情页展示当前 Run、执行树（`runs[0]` 是真根）与后代 Trace 事件；关联日志按根 Run 服务端分页加载，每页 50 条，`total` 随响应返回，可以查到第 500 条之后。响应里的 `X-Request-ID` 可直接粘进日志 Tab 过滤。页面会显示 `dropped_count`（累计丢失日志条数，含队列满、写入失败等所有原因）与 `write_failures`（写入/清理失败次数，非条数）。这里是只读排查界面，不是日志采集配置中心。

**用户端聊天入口（/chat）**：侧栏「用户端聊天」进入无侧边栏的全屏聊天页，面向最终用户——顶部下拉选择 Agent（默认内置客服）。Agent 允许显示虚拟形象时，左侧陪伴栏大号展示它（无形象回退图标，3D 模型可拖拽旋转查看，模型内嵌说话动效时流式回复中自动播放嘴巴开合、回复结束静止；窄屏自动收起）；Agent 关闭显示后，聊天页不加载形象资源，对话区使用释放的宽度。多轮对话流式输出，工具调用只显示一行状态（正在执行/完成/失败），回复完成后按 markdown 渲染；「新会话」按钮换会话，切换 Agent 自动重开并跟随该 Agent 的显示设置。涉及人工确认的操作（如大额退款）会在气泡内出现「批准 / 拒绝」按钮，页面内即可完成审批，对话继续（后端校验 `run:approve` 权限并记录已认证主体；开发模式未开鉴权时才沿用 `decided_by` 标签）。**边界**：这是示例级入口——不做用户注册/多租户/会话列表持久化；请求复用工作台内存中的账号令牌或 API Key（`AUTH_ENABLED=false` 时无需提供）；生产环境的用户端请由业务系统自建，走 REST/SSE 调用 LubanAgent（接入写法见[改造指南](../customization/overview.md)）。

**流程图页面**：查看已注册确定性流程图（如退款流水线）的节点与分支拓扑——节点按类型着色（step / agent / 人工），条件分支虚线双出边标注，入口与汇点带 START / END 标记。只读视图，实时读图定义不触发编译；**编辑图走代码**（`app/graphs/`，改流程 = 改代码发版，保持流程的可测试与可审计），本页不做可视化设计器。图怎么写见[图编排](./graphs.md)。

**Prompt 库页面**：以 Prompt 为维度管理系统提示词——列表、新建、编辑发版（新版本不可覆盖旧版本）、版本历史、分配给 Agent（反查哪些 Agent 在引用）。分配即让目标 Agent 吃该 Prompt 的当前版：系统为每个被分配的 Agent 产生一个新版本，把 Prompt 全文解析进快照（语义见 [Prompt 库](./prompt-library.md)）。Agent 编辑器的指令区也是双轨：引用态显示 Prompt 只读预览与版本徽章，可一键"转为内嵌"；内嵌态可以选择挂到某个 Prompt 引用。

**模型中心页面**：大脑槽位可新增、编辑标识/名称/用途、改模型映射和删除，四个初始预设也可编辑。当前环境来自服务端，模型选择回填已有映射；改名保留旧标识兼容并移动所有环境映射。删除弹窗列出全部 Agent 历史版本的使用情况（主槽位、降级槽位和摘要依赖），有引用不能删除；后端会再次检查，并以 409 兜底并发新增引用。Agent 新建/编辑的主槽位、降级槽位，以及模型对比备注都使用动态目录，旧别名仍能展示。查看需 `config:read`，修改需 `config:write`；详见[模型中心](./models.md)。

**Agent 调试台**：进入某个 Agent 的调试台，是一个「对话 + Prompt 试跑」双 Tab 工作台。「对话」Tab 是围绕该 Agent 的多轮对话调试；「Prompt 试跑」Tab 并排试跑同一个 Agent 的两份 Prompt——左侧是库内定义的基线，右侧是你的修改。改 variables 即时生效；改 instructions 只是临时覆盖（本次试跑生效，不入库、不改 Agent 定义）。试跑内容可"从 Prompt 库载入"后继续改。两个 Tab 切换不丢状态，后台的流式输出也不会断流；对话与试跑各自的会话相互独立。

**虚拟形象（Agent 编辑器「身份」区）**：每个 Agent 可以上传一个展示形象——SVG / PNG 图片，或 GLB / GLTF 3D 模型（≤ 20MB）。「显示虚拟形象」开关默认打开；关闭后保存为新版本，聊天页不再展示形象区域，但已上传文件和文件名会保留，可以随时重新开启。上传和移除仍立即生效并各自生成新版本，也不会覆盖你还没保存的显示开关。旧 Agent 和旧版本没有这个字段时按打开处理。API：`POST /v1/agents/{key}/versions`（保存开关）、`PUT /v1/agents/{key}/avatar`（multipart 上传）、`GET /v1/agents/{key}/avatar`（取形象文件）、`DELETE`（移除）。形象是纯展示字段，不进模型运行逻辑；关闭显示不是删除或权限限制，已登录用户仍可按 API 取文件。文件落盘在 `data/avatars/`（env `AVATAR_FILES_ROOT`）。

调试相关的几个会话约定：
- **对话调试（调试台「对话」Tab）**：打开页面自动开一个新会话（生成新会话 ID），多轮对话共用；刷新页面即换新会话。Agent 若开了会话记忆，会按这个会话 ID 读写后端记忆，与页面显示的对话历史叠加生效。
- **Prompt 试跑（调试台「Prompt 试跑」Tab，并排试跑）**：每次点"并排试跑"都生成新会话 ID，原 Prompt / 修改后 Prompt 两条 Run 共用同一会话 ID——在 Trace 列表里成对可查，也避免上一轮的会话记忆污染本轮对比。试跑支持"从 Prompt 库载入"：选中一个 Prompt，把它的内容填进当前编辑态试跑（只影响本次调试，不改库里的 Prompt，也不改 Agent 定义）。
- **Trace 列表与详情**：显示每次 Run 的会话 ID 与用户标签（未传则显示 —），排查"这个用户/这通会话发生了什么"不用查库。Trace 记录的内容见[运行观测](./observability.md)。
