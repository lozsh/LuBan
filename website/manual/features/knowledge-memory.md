# 知识与记忆

> 本页讲最小 RAG 知识库、防错答守门的三个字段、知识库工作台管理，以及三种记忆策略。两者都是可选能力。

**知识库（最小 RAG）**：单知识库起步——文档解析（md/txt/pdf/docx/csv/json/html/xml 八种格式）、切块（大小与重叠可按知识源独立配置）、向量化、检索、带引用回答。定位是"够客服示例跑通产品问答"，不做多库联邦与复杂重排。

**防错答守门（可不答、不硬编）**：RAG 最怕的不是检索不到，而是检索到弱相关的片段后模型硬编一个答案。知识配置提供三个可选守门字段，全部由代码强制执行（不靠 Prompt 声明）：

```yaml
knowledge:
  sources: [product-faq]
  score_threshold: 0.2      # 相关度阈值：cosine 低于此值的检索片段直接丢弃（0 = 不过滤）
  no_hit_fallback: 抱歉，我暂时无法确认这个问题的答案，建议联系人工客服。
  max_age_days: 30          # 知识时效：超过 30 天灌入的片段丢弃（不填 = 不限）
```

- **score_threshold**：弱相关片段在进模型之前就被丢弃，宁缺毋滥。
- **max_age_days**：过期知识不进上下文（判定依据是灌入时自动打的 `ingested_at` 时间戳；没有时间戳的存量数据不受影响）。
- **no_hit_fallback**：过滤后一条都不剩时，Agent **直接用这句话作答，不调模型**——零 token 消耗，Run 正常完成（结束原因 `knowledge_no_hit`，事件流里有一条 `knowledge.no_hit` 可查）。不配这句话就保持旧行为：没有片段时模型照常回答。
- 三个字段全不配 = 行为与从前完全一样；`cite: false` 可关掉默认开启的"[n] 编号 + 只依据片段作答"引用约束。

阈值需要按 embedding 实测校准（不同向量的分数量纲不同）；换用真实 embedding 模型后记得重新灌库并重调阈值。向量模型用环境变量 `EMBEDDING_MODEL`（可选 `EMBEDDING_BASE_URL`/`EMBEDDING_API_KEY_ENV`）配置——不配时用内置的确定性演示向量，够跑通示例，不承诺生产检索质量。工作台的 Agent 编辑器"记忆与知识"区可以直接填这三个字段（阈值、兜底话术、时效天数，留空即不启用）；知识库页面的"检索测试"面板可以现场试查命中块与相似度分数，是校准阈值的直接工具。

**知识库管理（工作台「知识库」页面）**：知识源的增删改全程页面操作，不碰代码——上传多格式文档创建知识源（填名称、描述、切块参数，多文件一次成型）、查看每个切块的原文与来源文件、改切块参数后一键按新参数重新切块（上传的文件落盘保留，重切不用重新上传）、删除知识源（切块与文件一并清除）。页面建的知识源与代码种子源（如 `product-faq`）在同一列表展示，种子源标「内置」徽标、不可删；建好的知识源在 Agent YAML 的 `knowledge.sources` 里直接引用名字即可。每个上传文件限 10MB、单次上传总量限 50MB。页面入口见[开发者工作台](./workbench.md)。

**记忆**：三种策略按 Agent 选用——会话记忆（本轮对话）、摘要记忆（长程压缩）、长期记忆（跨会话关键事实，显式写入）。上下文组装遵守[成本治理](./cost.md)中的 KV-cache 不变量。

**原则**：RAG 与记忆都是**可选**，简单 Agent 不被复杂组件拖累。
