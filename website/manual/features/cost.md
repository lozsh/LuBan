# 成本治理

> 本页讲 KV-cache 友好不变量、Token 估算、Run 级预算熔断，以及费用公式与单价字段的配置。

**是什么**：上下文组装保证 KV-cache 友好不变量（稳定前缀、append-only，命中效果取决于厂商缓存语义）；Token 估算前置（近似值，调用前知道大概花多少）；Run 级预算与超限熔断（撞线即停，写进 Trace）；按 Agent/会话/天归集的费用报表与优化建议。

**为什么需要**：成本失控是真实账单事故（重试静默烧钱、上下文无限增长）；成本必须可治理在事前与事中，不是事后算账。

**费用怎么算**：单次 Run 费用 = `输入token/1000 × 输入单价 + 输出token/1000 × 输出单价`，单价写在模型注册的 `params` 里——`input_price_per_1k` 与 `output_price_per_1k`（每千 token 单价）。**调试台显示费用为 0，多半是模型没填这两个字段**（FakeLLM 或未配单价的真实模型都会是 0）。配了单价才会真实归因。这两个字段由框架计费层消费，不会透传给模型 SDK。

**边界**：预算熔断挂在 Runtime 上由代码强制（见 [Agent Runtime](./runtime.md)）；费用归因依赖每次 Run 的 Trace（见[运行观测](./observability.md)）。单价字段在模型注册时配置（见[模型中心与模型工厂](./models.md)）。
